# Кейс: AI-buddy — ИИ-наставник для стажёров (Hack&Change 2026, Авито)

Выжимка из `Авито_кейс.pdf`, чтобы Claude и команда сверялись с требованиями без PDF.

## Задача

Прототип AI-buddy, который помогает стажёру освоиться в новой команде: разобраться в процессах и инструментах, получить ответы на рабочие вопросы, пройти выбранные этапы адаптации и выполнить действия через корпоративные сервисы. Пример из кейса: стажёру нужен отгул — бадди объясняет процедуру, помогает подготовить запрос через корпоративный сервис и показывает результат, не заменяя общения с наставником.

Сократить рутинные обращения к наставнику (40–48 ч за 6-месячную программу, 55–65 ч за 9-месячную), а не заменить содержательную работу наставника.

Фокус: 3–5 сценариев адаптации **или** один глубоко проработанный. Количество сценариев само по себе на оценку не влияет — важно реализовать весь заявленный функционал.

1. Описать путь стажёра в первые недели и выбрать сценарии (чек-лист Авито, свой опыт).
2. Научить помощника отвечать на вопросы о команде и инструментах с учётом контекста.
3. Реализовать все выбранные сценарии, хотя бы в одном — действие через корпоративный сервис или его имитацию (действие выполнено, если сервис/имитация возвращает отображаемый результат и сохраняет его).
4. Показать этапы адаптации, статусы задач и следующие шаги.
5. Обосновать архитектуру, работу с правами и подключение корпоративных сервисов.
6. Предложить метрики пользы и способ проверить эффект на стажёрах.

Участники: стажёр (основной пользователь), наставник (buddy), руководитель, HR BP. Отдельные интерфейсы для наставника/руководителя не обязательны.

## Пространство решений

- Интерфейс: чат, веб-сервис, расширение — на выбор.
- Корпоративные системы Авито: отсутствия, командировки, найм, увольнения, согласия, бенефиты, чек-лист новичка.
- Уже есть в Авито (имитировать API, не создавать заново): данные сотрудников, авторизация, ролевая модель, аналитика событий, настройка ИИ-агентов с промптами и MCP, внутренний ИИ-крон, feature flags (compile-time и runtime).
- Стек Авито: бэкенд преимущественно Go (Python+Flask — в отдельных случаях), PostgreSQL, Redis; фронтенд React + TypeScript, TanStack, Zustand, Zod. Оценивается совместимость архитектуры со стеком, а не использование всех технологий.
- AI-сценарии разрабатывать по SDD (spec-kit или OpenSpec); пригодятся промпты, скиллы, MCP.
- Инфраструктура Авито: Docker, Grafana, Clickstream, RPC/Apache Kafka, CI/CD. При отдельном размещении статического интерфейса нужен явный API-клиент.

## Ограничения

1. Основная аудитория — стажёры.
2. Синтетические или обезличенные данные, тестовые инструкции и имитации сервисов.
3. Тестовые инструкции не выдавать за регламенты Авито.
4. Реальные данные сотрудников и свои аналоги HR-систем не нужны.
5. Бадди учитывает права пользователя: недоступные сведения и операции не раскрываются и не выполняются.
6. Сценарии с чувствительными ПДн и финансовыми операциями — вне области задачи.
7. Покрытие строк прикладного кода команды автотестами > 80% (без зависимостей, сгенерированного кода и самих тестов).
8. Приложить воспроизводимый отчёт о покрытии и SDD-спецификации, по которым велась разработка AI-функций.
9. Простые локальные операции UI — ориентир < 1 с.
10. Обращения к LLM и внешним сервисам не блокируют интерфейс: статус ожидания, корректная обработка сбоев.

## Формат сдачи

PDF-презентация со ссылкой на репозиторий **или** ZIP с кодом и презентацией. Приватный репозиторий — доступ аккаунту жюри `hack-and-change-2026`. В сдаче:

1. Работающий прототип с интерфейсом и всеми заявленными сценариями.
2. Код и документация: README.md с инструкцией запуска (Docker или другой способ), версиями зависимостей, тестовыми учётными данными, порядком проверки и запуском тестов; SDD-спецификации, тесты и отчёт о покрытии.
3. Тестовые данные и имитации интеграций для воспроизведения сценариев.
4. Видеодемонстрация (файл в ZIP/репозитории или ссылка на первом слайде/в README): путь от запроса до результата.
5. Продуктовая презентация в PDF.

Внешние API: указать сервис, модель, переменную окружения и подключение ключа; организаторы могут использовать свой ключ. Пример конфигурации без секретов; для Docker — файлы запуска. После дедлайна версия фиксируется.

## Допуск (иначе 0 баллов)

- прототип не запускается по инструкции или эксперт не может пройти заявленный основной сценарий;
- нет исходного кода или инструкций, без которых невозможно запустить и проверить;
- нет продуктовой презентации.

## Что следует из материалов Авито

Подробная выжимка всех восьми источников — в скилле `hackkit:avito-context`. Главное:

- **Путь стажёра** — официальный чек-лист (общий и Backend), по неделям: доступы и каналы в первую неделю, документы команды, PaaS, Sentry, Grafana, SPT, Zero Bug Policy в первый месяц, экваторная встреча через 3 месяца, выпускной, опрос. Сид — `data/seed/onboarding-checklist.yaml`. Стажёры совмещают работу с учёбой (от 25 ч в неделю).
- **Платформа ИИ-агентов в Авито уже есть** — «Виталик» (оркестратор, RAG, MCP Hub, бенчмарки). Бадди — доменный агент этой платформы, а не новая платформа; наши мок-сервисы — MCP-серверы для её хаба.
- **MCP по-авитовски**: один инструмент — одна человеческая задача, мало инструментов, терпимость к вводу, компактные ответы, понятные ошибки.
- **Жюри — инженеры Авито**: принципы разработки и шаблон Tech Design Review из Playbook, чек-лист из разборов стажёрских заданий (запуск одной командой, слои, миграции, линтеры, loading/error/empty).
- **Интерфейс в духе дизайн-системы AKITA**: семантические токены, чёрный акцент, светлая и тёмная тема — без логотипа и шрифтов Авито.
